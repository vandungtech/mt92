## Compatibility result

No miner-side source changed. Both commits are confined to validator container
build inputs, coordinator deployment inputs, and coordinator reconciliation code.
The miner never builds the validator image, never runs the coordinator, and never
calls `microtensor.coordinator.collect.reconcile`.

### `3a3302e` — validator image

The validator base image moves from `python:3.11-slim-bookworm` to
`python:3.14-slim`, adds `cmake`, installs the `gguf` extra, switches to an
editable install, and replaces the `mt validator run` entrypoint with
`deploy/validator-entrypoint.sh`, which runs `mt validator env-setup` once when
`${MT_HOME}/evaluation-env/lock.txt` is absent. The healthcheck start period
grows from 2m to 10m to cover that first build.

Miner impact: none. These are validator operator inputs. The change does imply
that validators evaluate GGUF artifacts inside a pinned evaluation environment
built at first boot, which is consistent with — and does not alter — the
`code/mt-3g` GGUF submission contract this miner targets.

### `53e4df6` — `MT_RESULT_WORKER`

`reconcile()` gains an opt-in operator override:

```python
result_worker = os.environ.get("MT_RESULT_WORKER", "").strip()
if result_worker:
    preferred = [r for r in deciding if r.worker_hotkey == result_worker]
    if preferred:
        deciding = preferred
```

When set to a worker hotkey that appears among the deciding reports, the whole
quality/publishability computation collapses to that single worker's report.
`deploy/docker-compose.coordinator.yml` merely forwards
`MT_RESULT_WORKER: ${MT_RESULT_WORKER:-}` into the coordinator container, so the
default remains empty and the behaviour stays off.

Miner impact: none *when unset*, and the miner has no legitimate reason to ever
set it. It is read from the process environment of a **coordinator**, not a
miner. However:

- The behaviour is unpublished and unanchored. It is not covered by the signed
  v0.3.2 runtime, by the mechanism version, or by any on-chain commitment.
- If it were ever set in an environment that also runs coordinator code, the
  resulting reconciliation would differ from every other participant's, and
  validators could compute different weights for the same round.

This audit therefore treats `MT_RESULT_WORKER` as forbidden configuration for
this repository. `ControllerConfig.from_env` refuses to load when the variable is
present with a non-empty value, and `tests/test_result_worker_guard.py` statically
scans the tracked configuration, deployment, and documentation surface to prevent
it being reintroduced. See also the "Non-negotiable safety rules" section of
`launch_todo.md`.
